# 0.5.0 release validation

Validated on 2026-11-15. Baseline: `2a294b180daefe0511e253905b685de68d761175`
(main, version 0.4.1). Candidate code: `8960979`, version 0.5.0.
Later documentation-only commits do not change the tested implementation.

## Tests and packaging

- 287 tests passed on each CI target: Python 3.10.22, 3.11.18, 3.12.14, and 3.13.5.
- Ruff lint and format checks passed.
- Coverage: 91% overall, 100% for the import-boundary rule.
- The installed wheel passed all 287 tests with current PyPI dependencies.
- Wheel and source distribution passed Twine validation and isolated functional
  checks for version metadata, opt-in behavior, remediation guidance, and the
  CLI failure gate. The wheel was built from the source distribution by `uv build`.
- Configured policy checks found 28 expected urllib3 imports in Requests, 79
  Werkzeug imports in Flask, and 115 Starlette imports in FastAPI. A nonexistent
  forbidden module produced no boundary diagnostics in those projects.
- JSON and SARIF, both configuration formats, relative imports, src layouts,
  type-checking blocks, nested imports, negative fixtures, suppression, invalid
  configuration, and disabling lint are covered by automated tests.

## Public-source corpus comparison

All 29 default packages from `uv run --frozen python benchmarks/run_corpus.py`
were scanned, totaling **10,330 Python files**. Sources are cached PyPI
source distributions, not arbitrary working copies. These checks exercise
PyCodeGate against those projects; they do not run the projects' own test suites.

Each source tree was scanned separately with baseline and candidate code using
`--json --no-dead-code`. Scores, discovered project metadata, and all diagnostic
fields were compared after sorting diagnostics. Only version and elapsed time
were excluded. **Every comparison was identical.** No new default restrictions
are introduced for projects without import-boundary configuration.

The corpus emits 19,376 existing diagnostics with a mean score of 52.8. These
findings were not individually adjudicated as true or false positives. Identical
output demonstrates lack of regression for this release, not that those projects
are broken or that existing rule precision has been fully established.

## Version and publication

PyPI and remote Git tags were checked: the latest published version was 0.3.0;
0.5.0 was unused. The minor version reflects the new opt-in capability on top of
the unreleased 0.4.1 checkout. `pyproject.toml`, `uv.lock`, installed metadata,
CLI JSON, and distribution names agree on 0.5.0.

The existing release workflow publishes to PyPI through trusted publishing when
a GitHub release is published. Local validation does not establish a merged PR,
passing hosted CI, a published GitHub release, or successful PyPI publication.
